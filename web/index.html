Segmentos válidos: database tables data views functions others

Instalar y operar backupctl en el servidor. Requiere DEPLOY_HOST en el perfil.

1 · Instalar o actualizar allí

Copia bin/, lib/ y el env.sh al servidor. Los respaldos y logs que ya haya allí no se tocan.

2 · Traer el estado al repositorio

Escribe ESTADO.md con lo que hay realmente allí: versión, crontab, respaldos y diagnóstico.

3 · Operar el servidor desde aquí

Cada botón ejecuta la orden en el servidor, con la salida en vivo. Es lo mismo que entrar por SSH.

Copiar las bases de datos a OTRA máquina. Esto no es un respaldo: es un traslado.

Migrar a otro servidor

Copia las bases de datos a OTRA máquina, que debe tener backupctl desplegado. Compara los recuentos al terminar.

Cron

En HestiaCP, instalar el cron necesita sudo. Sin terminal donde teclear la contraseña, esto solo funciona si sudo no la pide. Si falla, hazlo desde el terminal.

Avisos

Claves Restic de HestiaCP

Es el env.sh del perfil. Se valida la sintaxis antes de guardar, y la versión anterior queda como env.sh.anterior.

Contiene la contraseña de MySQL en claro. Es tu archivo, en tu equipo, pero tenlo en cuenta si hay alguien mirando.

Añadir un servidor

Se comprueba la conexión, se escribe el env.sh y, si lo pides, se despliega.

Acceso a MySQL

La contraseña del usuario nuevo se genera aquí (28 caracteres) y se guarda en el env.sh. La de administrador se usa una vez y se descarta.

Acceso por clave SSH

Se usará tu contraseña una sola vez para dejar instalada tu clave pública en el servidor. A partir de ahí no se vuelve a pedir: ni aquí, ni en el cron, ni en los guiones.

Si no tienes clave, se genera una (ed25519). La contraseña no se guarda en ningún sitio.
